# Project Dugout

**한 이닝, 어디까지?** 투수의 구종 배합을 읽고 노릴 공을 정한 뒤, 같은 투수를 상대로 3아웃 전까지 득점하는 웹 야구 게임입니다.
첫 화면의 **타석에 서기**에서 바로 플레이합니다. 한 이닝만 제공합니다. 이전 3D·투구·9이닝·단장 모드의 메뉴와 실행 진입점은 제거했으며 Git 이력에서 확인할 수 있습니다.

### 기본 모드: 한 이닝 승부

- 투수 리포트에서 기본 구종 비율을 확인합니다. 투수마다 3개 구종을 갖고 있으며 강속구형·완급 조절형 등 성향이 다릅니다. 비율은 다음 공의 정답이나 한 판의 고정 구성표가 아닙니다. 2스트라이크에는 느린 공·유인구, 3볼에는 빠른 공·존 공략 비중이 늘어납니다.
- **빠른 공 / 느린 공 / 맞히기** 중 노림수를 선택하고 **투구 받기**를 누릅니다. 터치·클릭·Space를 누르는 순간 스윙하며, 누르지 않으면 참습니다. 노림수는 투구 전에만 바꿀 수 있습니다.
- 노린 구속대가 맞으면 장타 기회가 생깁니다. 예상 밖의 공도 정확하게 맞히면 안타가 됩니다. 맞히기는 대응 범위가 넓지만 단타만 가능합니다. 입력 타이밍·노림수·도착 코스로 판정하며 추가 무작위 안타 판정은 없습니다.
- 볼·스트라이크 카운트가 타석 안에서 누적됩니다. 4볼은 볼넷, 3스트라이크는 삼진, 2스트라이크 이후 파울은 카운트를 유지합니다. 약한 타구는 아웃이며 **3아웃이면 이닝 종료**입니다.
- 안타 때는 모든 주자가 안타의 루 수만큼 진루합니다. 볼넷은 밀리는 주자만 진루합니다. 홈런은 타자와 모든 주자가 득점합니다. 도루·병살·희생타·실책·추가 진루 판단은 생략한 간단한 공격 이닝입니다.
- 포심·투심·슬라이더·커브·포크·커터·체인지업 프로필을 사용합니다. 구위는 구속·움직임·회전, 제구는 목표 코스의 오차를 바꿉니다. 3×3 존의 볼 중심 도착 좌표로 볼/스트라이크를 판정합니다.
- 초반 코스·무브먼트 차이는 부드럽게 압축하고 후반에 드러냅니다. 구속별 도착 시간과 최종 판정 위치는 유지합니다. 타격은 입력 순간의 공 위치에서 짧게 멈춘 뒤 뻗으며, 파울·땅볼·뜬공은 다른 방향으로 움직입니다. 이 효과는 판정 시간을 바꾸지 않으며 동작 줄이기 설정에서는 정적인 표시를 사용합니다.
- 동일한 구면 실밥을 구종별 회전축·회전수·그립으로 회전시킵니다. 읽기 쉽도록 시각 회전은 실제 RPM의 7.5%로 늦추고 비행 시간도 늘렸습니다. 구종·구속은 투구 결과에서 공개합니다.
- 같은 투수 재도전은 시드가 같으므로 같은 판단과 카운트라면 같은 공이 재현됩니다. 다른 선택으로 카운트가 바뀌면 후속 배합도 바뀝니다. 최고 득점은 이 브라우저에 저장하며 이전 10구 점수 기록과 분리합니다.
- 일시정지·창 이탈 뒤에는 미완료 공을 다시 받습니다. 이미 완료된 투구의 카운트·득점은 유지합니다.

### 인터페이스 원칙과 검증

선택할 때에는 경기장 자리에 큰 궤적 그림 카드 세 개를 표시합니다. 투구가 시작되면 카드는 사라지고 경기장과 스윙만 남습니다. 본 조작은 16px, 보조 글자는 최소 14px를 기준으로 하며 rem 단위로 확대됩니다. 타격 뒤에는 주자 이동과 홈인 순서에 맞춰 득점을 표시합니다. 경기 중에는 득점, B/S/O, 주자를 표시합니다. 배합은 투구 전 리포트에서, 규칙은 도움말에서 확인합니다. 노림수에는 짧은 글자 라벨을 유지하고 뒤로·도움말·일시정지에만 익숙한 아이콘을 사용합니다. 모바일 하단에 노림수와 스윙을 모으고 터치 버튼은 44px 이상 확보했습니다. 가로 화면에서는 조작부를 오른쪽에 둡니다.

[NN/g의 AI 프로토타입 평가](https://www.nngroup.com/articles/ai-prototyping/)에서 지적한 정보 위계·색상 과용·부적절한 패턴 문제, [아이콘의 의미와 라벨](https://www.nngroup.com/articles/icon-usability/), [W3C 터치 대상 크기](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum)를 참고했습니다. 자동 검증은 320×568, 390×844, 844×390, 1440×1000에서 진행하며 실제 사용자의 재미·재도전율은 아직 검증하지 않았습니다.

```sh
python3 -m http.server 8000 --directory web
node --test tools/check-quick-game.mjs tools/check-quick-pitches.mjs tools/check-quick-feedback.mjs
PLAYWRIGHT_MODULE=/path/to/playwright/index.mjs node tools/check-quick-ui.mjs
```

구종·투수 능력·구면 실밥은 `web/js/quick-pitches.js`, 한 이닝 규칙은 `web/js/quick-game.js`, 화면·입력은 `web/js/quick-mode.js`, 스타일은 `web/css/quick-game.css`에 있습니다.
구종 특성은 [MLB 구종 설명](https://www.mlb.com/glossary/pitch-types), [체인지업](https://www.mlb.com/glossary/pitch-types/changeup), [커브](https://www.mlb.com/glossary/pitch-types/curveball), [회전축 자료](https://baseballsavant.mlb.com/leaderboard/spin-direction-pitches)를 참고했습니다. 수치는 게임용 대표 프로필이며 실제 선수 데이터나 공기역학 시뮬레이션이 아닙니다. 실밥도 게임용 구면 모형입니다.

플레이: **https://baseball.ysw.kr/**

`web/js/main.js`가 한 이닝 화면을 직접 엽니다. 서버·빌드 도구 없이 정적 파일로 실행합니다. 이전 모드의 공용 자료와 개발 문서는 현재 실행 경로에 포함하지 않습니다. 검증은 위의 `check-quick-*` 명령을 사용합니다.
