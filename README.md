# Project Dugout

**2.5초, 칠까 참을까?** 9회 말 두 점 차에서 공의 궤적을 읽고 스윙하거나 참는 3D 웹 야구 게임.
짧은 끝내기 승부와 낮부터 야간까지 이어지는 9이닝 경기를 제공합니다. 결과 카드와 같은 초기 상황의 도전 링크를 공유할 수 있으며, 투수 편과 단장 모드도 함께 있습니다.

플레이: **https://baseball.ysw.kr**

빌드 도구 없이 브라우저에서 그대로 돌아갑니다. 서버가 없고, 세이브는 브라우저에 자동 저장됩니다. 파일 내보내기와 복구 저장본도 지원합니다.

## 검증

Python 참조 구현으로 시뮬레이션을 보정했습니다. 60시즌을 돌려도 리그 환경이 표류하지 않습니다.

목표는 **최근 KBO** 입니다. 2026 시즌 진행분의 10구단 합계에서 직접 계산한
값(타율 .269 · 득점 5.12 · 안타 9.28 · 홈런 0.95 · K/9 7.75 · BB/9 3.79)을 기준으로 맞췄습니다.

```
4000경기   타율 .267   득점 4.97   안타 9.34   홈런 1.02   K/9 7.75   BB/9 3.78
30시즌     타율 .268 → .267   득점 5.03 → 4.90   표류 없음
           우승 구단 7/10 · 1~10위 승률차 0.27 → 0.29 (경쟁 균형 유지)
타자 WAR 정점 28세     주력은 21세 정점 후 38세까지 -14점, 제구는 오히려 상승
드래프트 1라운드 평균 12.4 WAR / 4라운드 0.9 — 전체 1순위도 13%는 실패
```

`web/js/core/_valgames.mjs` 로 경기 엔진을, `proto/` 의 파이썬 검증기로
성장·부상·드래프트·시장을 재현할 수 있습니다.

```
node web/js/core/_valgames.mjs 4000
cd proto && python3 validate_dev.py   # 성장 · 노화
```

## 경기 보기

모든 경기 화면은 **3D 중계**로 시작합니다. 이전 보기 선택 메뉴는 표시하지 않습니다.
모바일의 **기록 · 화면 설정**에서는 배속과 기록을 확인합니다.
저장된 과거 시점 설정과 관계없이 3D 구장 로딩 후 경기를 시작합니다.

3D 중계는 Three.js 0.185.1을 경기 입장 시 불러옵니다. 외부 CDN이나 별도 빌드는
필요 없으며 GitHub Pages와 배포 ZIP에 동일한 모듈이 포함됩니다.
구장·조명·선수는 코드로 만든 초기 모델이며, 투구와 타구에 따라 카메라가 전환됩니다.
경기 결과와 공·선수 좌표는 기존 중계 타임라인을 공유합니다.
WebGL 로딩 실패나 컨텍스트 유실 시 재생을 기다리고 다시 불러오기 버튼을 표시합니다.

`check-live3d.mjs`는 소프트웨어 WebGL로 3D 전용 보기, 실제 경기 종료, 과거 보기 설정 무시,
크기 변경, 컨텍스트 유실과 로딩 중 종료를 검증합니다. 실제 휴대폰 GPU 성능은 별도 확인이 필요합니다.

## 한 이닝 승부 — 투수 편

시작 화면의 **마운드에 오르기**에서 9회 말, 두 점 앞선 1사 1·2루 상황을
플레이합니다. 직구·슬라이더·체인지업, 몸쪽·바깥쪽·낮은 코스,
존 안 승부·유인구를 고릅니다. 2실점 전에 아웃 두 개를 잡으면 성공이며
투구 수 제한 없이 3아웃 또는 승패가 결정될 때 끝납니다. 같은 상황 재도전은 같은 난수 시드를 사용합니다.

단장 모드의 세이브와 난수는 사용하지 않습니다. `inning-game.js`는 이 짧은
승부를 위한 별도 규칙 모델입니다. 타자의 성향, 구종 반복, 속도 변화,
볼카운트와 투구 수가 결과에 영향을 줍니다. 진루는 단순화했으며
도루·병살·실책·선수 성장·연속 스테이지는 아직 없습니다.

```sh
node --test tools/check-inning.mjs
node tools/check-inning-ui.mjs  # 동일한 Playwright 환경 변수 사용
```

3D 구장에는 입장 비율에 따른 관중, 내야석, 덕아웃, 불펜, 안전망과 주변
건물·나무를 추가했습니다. 맑음·흐림·저녁 배경은 날짜 기반 시각 연출이며
경기 엔진의 기상 판정을 바꾸지 않습니다. 돔은 실내로 그립니다.
전광판에는 이닝별 득점, R/H/E, B/S/O, 현재 타순과 다음 타자들, 마운드의 투수를 표시합니다. 홈런·3루타·먼 거리 캐치에는 판정과 같은 타구 좌표를 사용한 짧은 전광판 리플레이와 전용 카메라가 나옵니다. 현재 리그의 10개 구단은 홈 경기마다 각 팀 동물을 바탕으로 만든 고유 3D 마스코트를 내보내며 관중 반응에 맞춰 응원합니다.

중계 시점은 센터필드(투구), 하이 홈(타구), 측면(베이스 접전·선수),
전경(이닝 교대)으로 구분합니다. 배치·역할은
[Keystone Productions](https://keystoneproductions.net/the-essential-guide-to-camera-positions-in-baseball-broadcasts/)와
[WBSC 제작 지침](https://static.wbsc.org/assets/cms/documents/806d5c14-26d4-76df-4bf8-f600181f458c.pdf)을 참고하고 게임 화면에 맞게 조정했습니다.
단장 모드의 3D 투구 간 대기는 일반 3.4초, 파울 4.2초(1배속)입니다.

### 9이닝 경기

시작 화면의 **9이닝 경기**에서는 고양 헌터스 타선으로 부산 돌핀스를 상대합니다.
1회 초부터 투수로 수비하고, 매 이닝 말에는 타자로 공격합니다. 3아웃마다 조작판과 카메라가 바뀌며 양 팀 타순과 점수를 이어갑니다. 9회 이후
동점이면 연장 12회까지 진행하며 끝내기, 선공 팀 승리, 무승부를 구분합니다. 경기 시각은
1회 낮에서 시작해 이닝이 흐르면서 노을과 야간 조명으로 바뀝니다. 세 번째 아웃에는 공격수
퇴장과 수비 반응을 보여주며, 마지막 아웃에는 승리 팀이 투수와 포수를 중심으로 마운드에 모입니다.

상대 투수에게는 시드로 정해진 **문법**이 있습니다. "초구는 직구", "2스트라이크면 바깥쪽 결정구", "몸쪽 직구 다음은 바깥쪽 변화구"
같은 규칙 네 개와 단서 하나(포수 미트 위치 또는 투구 템포, 75~80% 신뢰)를 갖고 있으며 규칙은 80~90% 일관성으로 지켜집니다.
투수 이름표를 누르면 진짜 배합이 아니라 **이 경기에서 본 것**만 카운트별로 정리한 관찰 차트가 나옵니다.
7회 말부터 불펜 투수가 다른 문법으로 등판하고, 한 규칙에서 안타를 두 번 허용하면 그 규칙 하나를 바꾸며 화면에 알립니다.
같은 시드는 같은 문법과 같은 투구를 재현하고, 투구 생성은 플레이어의 예측 선택을 읽지 않습니다.
규칙 모델은 `web/js/pitcher-grammar.js`, 검증은 `node --test tools/check-pitcher-grammar.mjs` 입니다.

9명 타자는 서로 다른 컨택·장타·선구안·주력을 가지고 있습니다. 타자가 바뀔 때 이름과 타순에
맞춘 응원 패턴이 바뀌고, 구장 전광판의 현재 타순도 함께 이동합니다. 현재 버전의 선수 응원은
외부 음원 없이 WebAudio로 합성한 북·박수·짧은 구호입니다.

```sh
node tools/check-full-game.mjs
node tools/check-full-game-ui.mjs
node tools/check-mascots.mjs
node tools/check-mascots-ui.mjs
```

### 타자 편

시작 화면에서 **타자로 뒤집기**를 고르면 두 점 뒤진 9회 말, 1사 1·2루에서
타선을 이어 플레이합니다. 상대 투수의 성향과 최근 투구를 보고 노릴 구종,
짧은 스윙·장타 스윙을 선택한 뒤 **스윙한다 / 지켜본다**로 한 구를 진행합니다.
현재 구종은 선택 후 공개됩니다. 상대 투구 생성은 사용자의 선택을 읽지 않습니다.

슬로모션 중 **스윙**을 누른 시점이 타이밍입니다. 시계의 초록 구간에서 누르면 컨택과 타구 질이 오르고,
이르면 당겨 친 약한 타구, 늦으면 밀린 약한 타구가 되며 파울 확률이 늘어납니다. 누르지 않고 예약한 스윙이
그대로 나가면 보정 없는 자동 스윙입니다. 결과 아래에는 같은 공에서 반대 선택을 했을 때의 결과가
"참았다면 볼"처럼 표시되고, 타석이 끝나면 다른 선택이 나았던 공 목록이 재도전 버튼 위에 나옵니다.

구종·코스 예측이 맞으면 보상은 숨은 보정치가 아니라 **정보**입니다. 읽기 창이 더 일찍 열리고
공이 더 빨리 선명해지며, 시계의 타이밍 적중 구간이 넓어집니다. 예측이 틀려도 창은 좁아지지 않고
컨택 확률만 조금 내려갑니다. 투구 자체와 지켜보기 판정은 예측과 무관합니다.

#### 밸런스 시트와 스킬 사다리

타자 편의 조정값은 `web/js/batting-tuning.js` 한 곳에 있고, 컨택은 단장 모드와 같은 로그오즈 가산 모델입니다.
층별 계수와 목표, 측정 결과는 [`proto/DESIGN_BATTING.md`](proto/DESIGN_BATTING.md)에 있습니다.
설계 원칙은 하나입니다. 실행(존 판단·타이밍)은 준비(구종·코스 예측)를 구할 수 있지만, 준비는 실행을 대신할 수 없습니다.

```sh
node tools/measure-batting.mjs 2000 200     # 정책별 컨택·안타·클리어율과 9이닝 학습 정책 비교
node --test tools/check-batting-ladder.mjs  # 무작위 < 존 판독 < 타이밍 < 예측의 순서와 간격을 지키는지
```

3아웃 전에 3득점하면 끝내기 성공입니다. 동점으로 이닝이 끝나면 성공으로
처리하지 않으며, 투구 수 제한은 없습니다. 투수 편과 마찬가지로 같은 시드 재도전과
새 상대 도전을 제공하고 단장 세이브는 사용하지 않습니다.

```sh
node --test tools/check-batting.mjs
node tools/check-batting-ui.mjs
```

투수 편은 코스를 고르고 ‘투구 시작’ 후 움직이는 릴리스 표시를 ‘지금 놓기’로
멈춥니다. 표시된 오차가 실제 투구 위치에 반영되며, 중앙에 맞추면 목표 근처로
갑니다. 제한 시간이 지나면 늦은 릴리스로 처리합니다. 목표와 실제 위치는
존 위의 연결선으로 비교할 수 있습니다.

‘숨 고르기’는 다음 공의 게이지 흔들림을 줄입니다. 주자·볼카운트·실점이 긴장도에
영향을 주며 숨겨진 제구 벌점은 없습니다. 몸쪽·바깥쪽·낮게·높게를 선택할 수 있고,
높게 + 직구 조합으로 하이 패스트볼을 던집니다. 유인구는 존 바깥을 목표로 합니다.
타자 편에도 높은 공 예상이 제공됩니다.

### 한 이닝 화면과 판정 표시

- 코스는 포수 시점의 스트라이크 존 그림에서 선택합니다. 점선 원은 목표,
  숫자 점은 마지막 투구가 실제로 들어온 위치입니다. 게임 내부의 정규화된
  판정 좌표를 표시하며 공식 ABS 시스템을 재현하는 것은 아닙니다.
- 타자 편은 지난 공 위치만 표시합니다. 이번 공은 홈에 도달한 뒤 표시하고,
  타구 결과는 수비 장면이 끝난 뒤 공개합니다.
- 선택 중에도 3D 구장이 화면 전체를 채웁니다. 점수·B/S/O·주자 다이아몬드로
  상황을 표시하고, 중복 헤더와 목표·조작 설명은 경기 화면에서 생략합니다.
- 하단의 스윙·지켜보기·준비 완료 버튼은 같은 위치에 유지합니다. 타자 편의
  구종·코스·타격 방식은 준비 중에 펼쳐 둡니다. 모바일 투구 중에는 스트라이크 존의 읽기 범위와
  스윙·참기 버튼만 남기고, 투구가 끝나면 선택판을 복원합니다.
  투수 이름과 성향은 점수판 아래에 따로 표시합니다. 투수 편은 ‘투구 선택’을 사용합니다.
- 결과는 판정·구속과 존의 투구 번호로 표시합니다. 브라우저 전체 화면 권한은
  요청하지 않습니다.

타자의 예상 코스는 존 형태의 상하좌우 버튼으로 선택합니다. 구종에는 궤적,
컨택·장타에는 타격 아이콘을 함께 표시합니다. 스윙·지켜보기는 기본 행동 선택,
준비 완료는 승부를 시작하는 주 버튼으로 구분합니다.

시작 시 투수의 마운드 입장과 타자의 타석 입장을 보여줍니다. 입장하는 선수 위에는
이름과 투구 성향 또는 타격 성향·주력을 잠깐 표시하며, 타자 교체에도 적용합니다.
타자 모드 준비 중에는 투수 머리 위 이름표를 누르면 이 경기에서 관찰한 구종 비율과 카운트별 기록, 구속 범위를 확인할 수 있습니다.
이름표는 카메라를 따라 움직이고, 투구 중이나 선수가 화면 밖에 있으면 숨깁니다. 수비 장면은
포구 직전 근접 카메라로 전환하고, 포구하면 글러브에 공을 유지합니다.
안타는 착지·바운드·추격을 표시합니다. 한 이닝 모드는 타구 속도·발사각·방향에서 중력·항력·바운드·펜스 충돌을
계산하고, 수비수의 반응 시간과 이동 속도로 포구 가능 여부를 정합니다.
판정과 화면은 같은 좌표 기록을 사용합니다. 펜스 높이 위로 넘어가면 홈런,
아래에 맞으면 반사되고, 땅볼 아웃은 1루 송구와 타자 도착 시간을 비교합니다.
주자별 주력·가속·출발 반응과 베이스를 도는 시간을 계산합니다. 수비는 송구 준비,
공의 이동 시간, 받는 야수의 커버 시간을 비교해 한 차례의 송구 또는 직접 베이스를
밟는 플레이를 선택합니다. 주자도 다음 베이스의 도착 시간을 예상해 진루를 선택하며,
실제 송구와의 경합으로 세이프·포스 아웃·태그 아웃을 정합니다. 1·2·3루타는 타자가
도달한 베이스에서 나오며, 추가 진루에 별도 확률이나 6.3초 기준을 쓰지 않습니다.
주자와 공 모두 판정에 사용한 좌표 기록을 재생합니다. 현재 수비 전략은 한 차례의
승부 송구를 선택하는 모델이며, 연속 중계·협살 판단까지 구현한 것은 아닙니다.

타자 편 카메라는 타석 안의 눈높이에 머뭅니다. 구장을 드래그해 좌우와 발밑을
둘러보고, 홈플레이트 아이콘으로 플레이트와 정면을 번갈아 볼 수 있습니다.
드래그는 화면을 잡아 끄는 방향입니다. 오른쪽으로 끌면 시선이 왼쪽으로, 아래로 끌면 위로 향합니다.
둘러보기는 좌우 60도, 상하 30도의 곁눈질이며 손을 떼면 투수 쪽으로 돌아옵니다. 플레이트 보기는 토글이라 그대로 유지됩니다.
투구를 시작하면 시선을 투수 쪽으로 돌리고, 투구 중 둘러보기는 잠급니다.
타구는 중계 카메라로 따라간 뒤 다음 공 전에 타자 시점으로 돌아옵니다.
타석이 끝나면 퇴장·입장 장면을 보여줍니다. 삼진 타자는 몸을 숙여 걸어 나가고,
다음 타자는 이름 표시와 함께 걸어 들어옵니다. 입장 때 투구 번호를 초기화하며
3아웃으로 끝나면 다음 타자를 등장시키지 않습니다.

한 이닝 모드는 현장음을 기본으로 켜며, 상단 소리 버튼의 설정을 기억합니다.
선택·투구 중에도 낮은 북·박수·응원 구호가 이어지며, 타격 순간에는 탄성, 결과에는 환호·박수·탄식으로 반응합니다.
새 모드에서는 멜로디와 높은 판정음을 생략합니다. 환호 시 3D 관중이 움직이며,
탭을 숨기면 음소거하고 나가기/재도전 시 이전 오디오를 정리합니다. 실제 녹음 응원가는 아닙니다.

스트라이크 존에는 현재 타석의 모든 투구를 1구부터 누적합니다. 겹친 번호는 연결선으로
실제 위치를 가리키며, 다음 타자가 들어오면 지웁니다. 총 투구 수는 표시하지만 강제 종료 제한은 없습니다.
타자는 구종 외에 몸쪽·바깥쪽·낮은 공을 예상하거나 전체 코스에 대응할 수 있습니다.
예상 코스는 초록색으로 표시하고, 코스 적중/실패는 컨택과 안타 확률에 영향을 줍니다.
예상 선택으로 상대의 실제 투구가 바뀌지는 않으며 지켜보기 판정에도 영향을 주지 않습니다.

타자 편은 예상 구종·코스·타격 방식을 고른 뒤 투구를 시작합니다. 공이 날아오는 중간에
2.5초 슬로모션 판단 구간이 열리며 스윙/지켜보기를 선택합니다. 시간 초과는 투구 전에 선택한 기본 행동을 실행합니다.
판단 중에는 최종 투구 위치와 결과를 공개하지 않습니다. 구종·코스는 투구 시작 때 확정하며,
결정 이후에도 같은 공을 이어 재생합니다. 타자 뒤쪽 시점으로 궤적을 확인할 수 있습니다.

공유 링크 `?challenge=b7-<stage>-<seed>`는 경기 번호(0~2)와 초기 시드를 전달합니다. 결과 점수나 개인정보는
URL에 넣지 않습니다. 같은 시드와 같은 선택은 같은 판정을 재현하지만, 선택에 따라 이후
볼카운트와 상황이 달라질 수 있습니다. 결과 카드는 기기에서 생성하며 검증된 랭킹이 아닙니다.

컨택 모델을 로그오즈 계수 표로 바꾸면서 새 공유 도전은 b7 버전입니다. 이전 b1~b6 링크는 같은 승부로 재현하지 않습니다.

선수 특성은 경기 판정과 같은 데이터를 사용합니다. 타자 편에서 컨택은 공에 맞힐 확률,
장타력은 타구 속도에 반영됩니다. 선수 패널은 주자별 주력과 수비 배치별 주력·송구를
보여주며, 야수별 주력·반응 시간은 포구, 송구력은 공의 베이스 도달 시간에 반영됩니다.
베이스 표시를 누르면 주자 정보를 열 수 있습니다. 주루 진루 판단은 자동이며,
타구 방향 지정·중계 송구·협살은 아직 지원하지 않습니다.

렌더링은 CSS 픽셀당 최소 1픽셀을 유지하고 DPR 2까지 지원합니다. 추가 샘플링은
400만 픽셀 예산을 적용하며, 4K처럼 화면 자체가 더 큰 경우에는 원래 화면 해상도를
우선합니다. 그림자 맵은 2048입니다. 저사양 기기의 성능은 별도 실기기 확인이 필요합니다.

홈런 표시는 타구가 담장을 넘는 순간 나옵니다. 환호와 함께 야수는 멈춰 공을
바라보고, 주자들의 베이스 한 바퀴 연출은 계속됩니다. 주루 완료 후 홈런 알림을 반복하지 않습니다.

선수 표현은 실제 비율·야구 동작을 우선하는 세미리얼 방향입니다. 현재 기본 모델에
선수마다 다른 호흡·체중 이동과 머리 시선 추적을 적용했습니다. 대기 동작은 렌더링만
바꾸며 판정 좌표를 변경하지 않습니다. 동작 줄이기 설정에서는 반복 대기 동작을 생략합니다.

송구·주루 보정(b5): 타자 주력은 7.4·8.2·9m/s, 출발 가속도는 5m/s²입니다.
기본 리드는 1루 3.4m·2루 3.6m·3루 2.7m이며, 준비 화면과 타구 판정의 시작 위치가 같습니다.
뜬공 때는 귀루 후 출발하며, 각 베이스를 통과하는 곡선의 이동 거리와 코너 감속을 사용합니다.
야수 추격 속도는 기존 값을 유지했습니다. 송구력은 포지션별 31~43m/s 범위이며
짧은 송구는 힘을 줄입니다. 받는 야수의 커버가 늦으면 릴리스를 늦추고, 이미 날아가는
공을 느리게 만들지 않습니다. 이 수치는 실제 측정 범위를 참고한 게임용 보정이며,
송구는 여전히 단순화된 궤적입니다. 중계 송구·협살·도루 선택은 아직 없습니다.

한 이닝 응원은 타자 입장 시 시작하며, 이름·타순에서 고른 세 가지 원본 북·박수 패턴과
짧은 저음 모음 구호를 사용합니다. 좌우에서 구호를 주고받고 짧은 경기장 잔향을 더합니다.
구호는 한 번에 약 0.18초 앞까지만 예약하며, 투구 때는 박자를 유지하고 타격·판정 때는
예약 음원을 취소해 환호로 전환합니다. 이름을 명확하게 읽는 음성이나 기존 구단 응원가는
포함하지 않습니다. 모든 소리는 브라우저에서 합성합니다.

경기 UI는 가상 팀 항구 웨일즈와 산성 폭스를 사용하며, 구장 전광판과 결과 카드에도
같은 팀명을 표시합니다. 점수판은 팀별 두 행 아래에 세로 B·S·O와 대칭 루상 아이콘을 배치합니다.
종료 화면은 점수, 같은 상황 재도전, 새 상대, 결과 공유 순으로 구성하고,
링크 복사와 카드 저장은 보조 버튼으로 나란히 둡니다. 모바일 가로 화면에서는 두 열로 배치합니다.

타자 편에는 세 경기가 있습니다. 항구 파크는 1사 1·2루 두 점 차,
산성 필드는 동점 1사 3루와 송구가 약한 외야진, 센트럴 돔은 동점 2사 만루 풀카운트입니다.
구장·유니폼·상대 투수·시작 카운트·점수는 같은 스테이지 데이터에서 결정됩니다.
산성은 석양, 항구는 맑은 낮, 마지막은 돔 환경이며 펜스 규격은 타구 계산에도 적용합니다.
어느 경기든 바로 선택할 수 있고, 승리하면 다음 경기로 넘어갑니다. 클리어 표시는 이 브라우저에 저장합니다.
타격 품질은 보너스 상한 적용 뒤에 컨택 스윙, 코스 예측 실패, 구종 예측 실패와 존 밖 타격의
배율을 적용합니다. 따라서 장타형 타자의 보너스가 빗맞힘 불이익을 지울 수 없습니다.

타자 모드의 담장 밖 홈런은 타구 직후 짧은 근접 카메라와 빠던을 보여줍니다.
주자의 실제 좌표와 득점 판정 시간은 그대로 유지하며, 홈런 표시는 담장을 넘을 때 나옵니다.
끝내기 득점 후에는 동료 다섯 명이 홈으로 모이고 포수·심판은 비켜 줍니다.
4.2초 동안 환호·박수와 기존 관중 함성을 보여준 다음 결과·다음 경기 화면으로 전환합니다.
희생플라이와 밀어내기 끝내기에도 적용하며, 모션 감소 설정에서는 점프와 반복 동작을 줄입니다.

선수는 Blender에서 제작한 공통 GLB 모델(`web/models/athlete.glb`)을 사용합니다.
원본은 `assets/players/athlete.blend`, 재생성 스크립트는 `tools/blender/build-player.py`입니다.
