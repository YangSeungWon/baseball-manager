## 진루 모델 — 시간표 (`run.js`, JS 구현)

> 파이썬 참조 구현(`game_engine.py`)은 아래의 확률 표(`ADV`)를 쓴다. JS 는
> 2026-09 부터 표 대신 **시간표**로 진루를 정한다. 검증 수치는 같은 구간을 맞춘다.

주루는 확률이 아니라 시간이다. 플레이마다 시간표를 만든다.

```
공이 야수 손에 들어오는 시각   ballClock()   닿았으면 그 자리, 빠졌으면 굴러가 멎은 곳 + 줍는 시간
송구가 베이스에 닿는 시각      throwArrive() 잡고 던지기(내야 .45s · 외야 .75s) + 거리/속도(어깨) + 중계
주자가 베이스에 닿는 시각      runArrive()   리드 4.2m, 주력 6.55+0.38z m/s, 뛰던 주자는 ×1.12, 타자는 첫 발 .25s
주자의 판단                    dares()       내가 먼저 닿는가 — 오차 σ=.35, 약간 공격적(-.05), 태그업은 신중(+.15)
송구의 실행                    execNoise()   내야 σ=.20 · 외야 σ=.45, 악송구 4.5%×exp(-.30z 어깨)
```

- **안타**: 타자의 베이스는 타구가 정한다(`hitBases`). 주자는 최소한 그만큼 밀려 가고,
  한 베이스 더는 송구보다 먼저 닿을 것 같을 때만 뛴다. 송구는 선두 주자에게 가고
  뒤 주자는 그 틈에 간다. 뛰다 잡히면 **안타 — 주루사**. 내야 안타는 강제 진루만.
- **땅볼 아웃**: 병살은 2루 포스 + 1루 중계(피벗 .60s)가 타자보다 .50s 이상 빨라야
  돌린다. 아니면 더 확실한 쪽 — 선행 주자 포스(타자 세이프, 야수선택) 또는 1루.
  3루 주자는 홈 송구가 이길 때만 잡힌다. 2아웃이면 가장 가까운 포스.
- **뜬공 아웃**: 잡힌 뒤 태그업. 선두 주자부터 판단하고, 송구는 그에게 간다.
- **리드**: 1차 리드 = 3.2m + .55×담력(`daring`) − .45×투수 견제(`hold`), 1.8~5.0m.
  타구가 나갈 때는 +1.0m (2차 리드). 같은 리드가 도루 · 견제 · 진루에 다 쓰인다.
- **도루**: 세트에서 릴리스 1.30s(견제 좋은 투수 −.05s/z) + 투구 비행 + 팝타임 1.95s(어깨 −.06s/z) vs
  반응 .36s(판단력 −.03s/z) + (27.43 − 리드 − 0.5)/주력. 시도율은 표(`sb_attempt`) × exp(.35×담력).
- **견제**: 타석마다 7.5% × exp(.55×(리드 − 3.2) + .25×주력z + .30×견제z) 로 던진다.
  송구 .32s + 19.4m/32m/s vs 귀루 .22s + (리드 − 0.5)/주력. 던졌는데 돌아갔으면 화면에만 나온다.
- **주자의 판단**: `dares()` 의 치우침 −.05 − .14×담력, 오차 .35 − .06×판단력(`read`).
  죽어도 뛰는 주자와 절대 안 죽는 주자가 여기서 갈린다. 400경기: 견제사 .045/경기.

검증(1,500경기): 병살/1루주자 땅볼아웃 46% · 단타에 2루 주자 득점 54% ·
1루→3루 40% · 2루타에 1루 주자 득점 34% · 희생플라이 51% · 도루 77%.

### 송구의 선택
땅볼에 3루 주자가 뛰면 야수는 홈과 1루를 저울질한다. 평소엔 홈 송구가 .12s 이상 이겨야 던지고,
아니면 확실한 1루를 잡는다(점수는 준다). 7회 이후 1점차 안이면 .35s 늦을 것 같아도 던진다 —
잡으면 '홈 송구 아웃', 늦으면 '홈 송구 — 세이프' 로 타자까지 산다.
외야 안타에서 선두 주자가 한 베이스 더 갈 때, 송구가 .5s 이상 늦을 것 같으면 외야수는
그 주자를 포기하고 중계로 던져 뒤 주자를 묶는다 (뒤 주자는 더 못 간다).

### 얕은 외야 (`bip.js assign`)
45~68m 는 내야수가 물러나며 잡을 수도, 외야수가 달려 들어와 잡을 수도 있다 — 두 무리를
함께 경합시킨다. 한쪽만 보면 50~60m 뜬공이 19% 만 잡히는 빈 땅이 생겼다(지금 78%).
앞으로 달려 들어올 때는 ×1.12, 내야수가 등지고 물러날 때는 ×.88. 그만큼 기준 반응 시간을 .44s 로 올려 리그 환경을 맞췄다.

### 수비의 위험 선택 (`bip.js fieldIt`)
살짝 못 닿는 타구(여유 −.30s 까지)에는 몸을 던질 수 있다. 던질 확률 = .25 + .15×담력(`bold`)
+ .20(2아웃) − .18(득점권·2아웃 미만). 잡을 확률 = .18 + .32×(가까운 정도) + .06×수비z.
잡으면 아웃(다이빙 캐치), 놓치면 공이 12m 더 흘러 최소 2루타, 안 던지면 앞에서 안전하게 잡아 단타로 막는다.
300경기: 다이빙 캐치 .3/경기 · 놓침 .6/경기.

## 투수 교체 AI (규칙 기반)
```
피로도 f = clamp((상대타자수 - capacity) / span, 0, 1.5)
  선발 capacity = 9.0 + 0.15×체력,  span = 10
  불펜 capacity = 3.0 + 0.045×체력, span = 4

선발 교체: f ≥ 1.0 | (f ≥ 0.55 그리고 5회 이후) | 6실점 이상
불펜 교체: f ≥ 0.85 | (이닝이 바뀌었고 4타자 이상 상대, 불펜 3명 이상 남음)
마무리 투입: 9회 이후 & 리드 1~3점
```
피로도는 `Context`로 타석 엔진에 되먹임된다 (구위 -0.90×f, 제구 -0.70×f).
타순 회전(times through order) 페널티도 함께 적용된다.

## 선수 생성 원칙
잠재 재능 1개(latent talent) + 능력별 독립 노이즈, 상관계수 ρ = 0.55.
능력별로 ρ를 다르게 준다 (컨택 .55 / 삼진회피 .35 / 선구안 .40 / 주력 .20 / 수비 .15).
→ '컨택은 최고인데 파워가 없는 선수', '재능 대비 수비가 형편없는 선수'가 자연 발생한다.
포지션별 보정으로 C/SS/CF는 수비 요구가 높고 타격이 낮게, 1B/DH는 반대로 생성된다.

## v0.1의 알려진 한계 (의도적 미구현)
- **실책이 없다.** 타석 엔진에 ERROR 결과가 없어 자책점 = 실점이다. 수비 능력이
  BABIP으로만 반영된다. 야수 개인 수비를 넣을 때 함께 추가할 것.
- **수비는 팀 합산이다.** 타구 방향으로 담당 야수를 뽑지 않아 골드글러브 유격수
  한 명의 가치가 반영되지 않는다. 최우선 개선 항목.
- 번트 / 대타 / 대주자 / 고의사구 / 시프트 없음.
- 승리투수 판정이 근사치다 (선발 5이닝 이상이면 선발).
- 폭투 / 포일 / 견제사 / 주루사 없음.
